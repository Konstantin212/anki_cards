# Anki Deutsch: правила роботи для Codex

## Призначення проєкту

Проєкт створює колоду Anki `Deutsch_Begegnungen_A2_B1` для вивчення німецької за підручником **Begegnungen A2/B1**. Користувач надсилає зображення або текст зі словами, а агент розпізнає матеріал, додає український переклад і приклади та перезбирає пакет `.apkg`.

Спілкуйся з користувачем українською. Німецькі слова, форми й речення пиши за чинним німецьким правописом.

## Джерела даних і артефакти

- `words.json`: єдине джерело карток. Під час імпорту зображень не редагуй його вручну; використовуй `merge_words.py`.
- `word_utils.py`: спільна нормалізація, валідація записів і атомарний запис JSON.
- `merge_words.py`: перевіряє candidate JSON, відсіює дублікати й дописує нові записи до `words.json`.
- `image_queue.py`: показує нові або змінені зображення та позначає успішно опрацьовані файли.
- `image_import_state.json`: автоматично створений checksum-стан черги. Не редагуй вручну.
- `build_apkg.py`: генератор колоди й фінальна перевірка даних.
- `Deutsch_Begegnungen_A2_B1.apkg`: згенерований пакет. Після зміни `words.json` перезбери його.
- `deutsch.csv`: старий неповний експорт. Не оновлюй і не використовуй його як джерело, якщо користувач прямо цього не попросив.
- `Words/`: вхідна черга зображень. Користувач додає файли сюди; не перейменовуй, не переміщуй і не видаляй їх.
- `backups/`: незмінні знімки для відновлення. Не редагуй їх і не використовуй як актуальне джерело карток.
- `CLAUDE.md`: попередня документація проєкту. Використовуй її як додатковий контекст; фактична поведінка `build_apkg.py` і явна вказівка користувача мають вищий пріоритет.

Не змінюй ID колоди, ID моделі, назву типу нотатки, шаблони карток або CSS під час звичайного додавання слів.

## Формат `words.json`

Файл містить JSON-масив. Кожен елемент має рівно п’ять полів у такому порядку:

```json
{
  "word": "Übersetzer",
  "full": "der Übersetzer, -",
  "translation": "перекладач",
  "forms": "",
  "examples": [
    [
      "Meine Tochter möchte als Übersetzerin arbeiten.",
      "Моя донька хоче працювати перекладачкою."
    ]
  ]
}
```

Зберігай UTF-8, відступ у два пробіли, порядок полів і наявний стиль форматування. Не додавай коментарів у JSON. Нові записи дописуй у кінець масиву в порядку матеріалу користувача. Не сортуй і не переписуй наявні записи без окремого прохання.

### Іменники

- `word`: іменник без артикля, переважно форма однини; німецькі іменники починай з великої літери.
- `full`: артикль, іменник і показник множини так, як у джерелі: `die Frau, -en`, `der Übersetzer, -`, `das Getränk, -e`.
- Якщо джерело не подає множини або іменник її не має, не вигадуй показник: `der Bundestag`, `die Kleidung`.
- Для pluralia tantum збережи позначку на зразок `die Möbel (Pl.)`.
- `forms`: порожній рядок.

### Дієслова

- `word`: інфінітив; для зворотних дієслів збережи `sich`.
- `full`: порожній рядок.
- `forms`: `Perfekt: er hat/ist ... · Präteritum: er ...`. Для зворотного дієслова збережи займенник в обох формах: `Perfekt: er hat sich beworben · Präteritum: er bewarb sich`. Для безособового дієслова вживай `es`.
- Правильно вибирай `haben` або `sein`; не визначай допоміжне дієслово лише за перекладом.
- У `word` позначай межу відокремлюваного префікса символом `*`: `auf*stehen`, `an*fangen`, `mit*nehmen`, `sich vor*stellen`.
- Не став `*` у невідокремлюваних дієсловах із `be-`, `emp-`, `ent-`, `er-`, `ge-`, `miss-`, `ver-`, `zer-`, а також у невідокремлюваних запозичених дієсловах. Перевіряй реальну дієвідміну: `er steht auf` означає `auf*stehen`, а `er unterhält sich` означає `sich unterhalten`.
- У Präteritum пиши третю особу однини. Для відокремлюваного дієслова став префікс у кінець: `Präteritum: er stand auf`; для зворотного відокремлюваного дієслова: `Präteritum: er zog sich an`.

### Прикметники, прислівники та інша лексика

- `word`: словникова форма.
- `full` і `forms`: порожні рядки.
- `examples`: одне або два природні речення, якщо користувач не просить іншого.

### Мовні шаблони й готові фрази

Додавай Redemittel лише на пряме прохання користувача.

- `word`: повна німецька фраза; місця для підстановки позначай одним символом `…`.
- `full` і `forms`: порожні рядки.
- `examples`: зазвичай порожній масив `[]`, бо сама фраза вже є прикладом.

### Переклад і приклади

- `translation`: короткий природний переклад українською. Додавай лише ті значення, які відповідають джерелу або потрібні на рівні A2/B1.
- Для звичайного слова створи 1–2 короткі приклади рівня A2/B1. Кожен приклад містить два рядки: спочатку німецьке речення, потім точний український переклад.
- Приклад має показувати значення слова, керування дієслова, відмінок або типовий контекст. Для відокремлюваного дієслова покажи правильне розташування префікса хоча б в одному реченні.
- Не додавай HTML: шаблон картки сам оформлює переклад і приклади.
- Якщо артикль, множина, керування, Perfekt, Präteritum або значення викликають сумнів, перевір їх у надійному словнику. Не вгадуй.

## Обов’язковий робочий процес для зображень

1. Запусти `python3 image_queue.py pending` і працюй лише з файлами, які команда назвала новими або зміненими.
2. Переглянь кожне зображення. Витягни німецькі лексичні одиниці в порядку читання. Пропускай заголовки, номери вправ, інструкції, підписи до ілюстрацій та дублікати в межах самого зображення.
3. OCR використовуй лише як чернетку. Звіряй зображення перед записом, особливо `ä`, `ö`, `ü`, `ß`, великі літери іменників, артиклі, множину, дефіси, `sich` і відокремлювані префікси.
4. Для кожної одиниці підготуй повний запис із п’ятьма полями за правилами вище. Збережи весь batch як JSON-масив у `/tmp/anki_deutsch_candidates.json`. Не створюй candidate-файли в репозиторії.
5. Запусти суху перевірку: `python3 merge_words.py --dry-run /tmp/anki_deutsch_candidates.json`. Виправ усі помилки валідації та перевір список `ADD` і `SKIP`.
6. Запусти merge: `python3 merge_words.py /tmp/anki_deutsch_candidates.json`. Скрипт використовує той самий duplicate key, що й генератор: прибирає `*` і `…`, стискає пробіли та порівнює без урахування регістру. Він пропускає дублікати щодо `words.json` і всередині batch.
7. Перезбери `Deutsch_Begegnungen_A2_B1.apkg`. Перевір повідомлену кількість нотаток.
8. Лише після успішного merge та збірки познач опрацьовані зображення: `python3 image_queue.py mark <шляхи зображень>`. Позначай також файли, у яких усі слова виявилися дублікатами.
9. Повідом користувачеві кількість розпізнаних, доданих і пропущених записів, результат збірки та нерозпізнані місця.

Якщо хоча б одне слово на зображенні неможливо прочитати або перевірити, не позначай цей файл опрацьованим. Запитай користувача про проблемне місце, продовжуючи роботу з іншими зображеннями. Не змінюй наявну картку через дублікат без прямого прохання.

## Перевірка і збірка

Переглянь вхідну чергу:

```bash
python3 image_queue.py pending
```

Перевір і злий підготовлений batch:

```bash
python3 merge_words.py --dry-run /tmp/anki_deutsch_candidates.json
python3 merge_words.py /tmp/anki_deutsch_candidates.json
```

Якщо доступний Python із `genanki`, запусти:

```bash
python3 build_apkg.py
```

Якщо `genanki` не встановлений у системний Python, використай `uv` без створення файлів залежностей у проєкті:

```bash
uv run --no-project --with genanki python build_apkg.py
```

Успішна збірка завершується повідомленням `Wrote .../Deutsch_Begegnungen_A2_B1.apkg (N notes)`. Скрипт сам зупиняється, якщо після нормалізації знаходить дубль. Фіксовані model/deck ID та GUID від очищеного `word` дають Anki оновлювати картки під час повторного імпорту замість створення копій.
